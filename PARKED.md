## Performance and robustness
- **Remaining quadratics: `poly_chain2`, `fnchain`, `nested_lam`** (each under ~0.5 s at plausible sizes; `mutual_group` fixed 2026-10-17, 514 -> 99 ms at n=2000, by one group frame extended per member in resolve.rs). Causes (profiled 2026-10-17): `poly_chain2` is RUN time, `Env::get` walks a hops-deep frame chain from a `let` chain (src/frame.rs:53; fix: flat or shared frames, big); `fnchain` is `eval_annotation`/`run_pure` evaluating an i-call closure chain per annotation (fix: memoize pure applications); `nested_lam` is `ResolveDeep`: each application in `(fun a0 -> fun a1 -> ...)(1)(1)...` hands back a deep-resolved result type that is n-i levels deep (resolve_deep has 26 call sites). A cache across calls is NOT a local fix: binding a variable would have to invalidate every cached node that contains it (a reverse index). The real fix is lazy resolution (return types left unresolved, consumers resolve on demand), which touches those 26 sites. Why parked: low value. Trigger: a real program over ~2 s check or run time in one of these shapes. Evidence: u8-superlinear-remeasure-2026-10-16.md ("Remaining four quadratics"). Status: parked.
